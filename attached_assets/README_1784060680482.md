# Tower Climber — Godot Starter

A runnable skeleton of the core loop: tap to spawn heroes, they auto-attack the current floor's monster, floor clears trigger gold + floor increment, difficulty scales exponentially with wall breakpoints every 10 floors — the same math from the progression spreadsheet, ported directly into code.

## Setup (10 minutes)

1. Download Godot 4.3 (or newer) from godotengine.org — the standard build, not .NET, since this project uses GDScript.
2. Open Godot, choose "Import," and select this folder's `project.godot` file.
3. Press the Play button (or F5). It'll ask which scene is main — `Main.tscn` is already set as the default, so it should just run.
4. Tap/click anywhere in the tower area to spawn a hero and watch the monster's HP bar drop. Tap a tab (Heroes/Soldiers/Weapons/Shop) to open the drawer.

## What's here vs. what's placeholder

**Real and working:**
- The exponential + wall-breakpoint difficulty formula (`set_enemy_for_floor` in `Main.gd`)
- The tap-to-spawn, auto-attack, floor-clear, gold-reward loop
- The persistent-tower-screen-with-collapsible-drawer UI structure you asked for

**Placeholder, meant to be replaced:**
- All visuals are default Godot UI widgets (labels, buttons, a progress bar) — no sprites, no tileset, no SNES-style music yet
- Drawer tab content is a single line of static text per tab — no real hero/soldier/weapon lists or shop yet
- No save/load, no daily login streak, no ads — those are your next milestones once the core loop feels good

## Where to tune the feel

Everything you'd want to experiment with first is at the top of `Main.gd` in the `TUNABLE ASSUMPTIONS` block — enemy growth rate, wall interval/multiplier, hero damage, attack speed, gold rewards. Change a number, hit Play, see how it feels. This mirrors the Assumptions tab in the spreadsheet on purpose, so the two stay easy to keep in sync.

## Suggested next steps, in order
